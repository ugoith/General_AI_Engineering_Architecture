# 数据模型

> 用途：让"数据长什么样、哪些约束必须永远成立"有一个权威出处，改字段前先读这里。
> 何时更新：实体、字段、枚举、不变量、存储方式变化时；破坏性变更必须先写 ADR 并给迁移方案。

## 1. 实体表

| 实体 | 说明 | 关键字段 | 存储位置 | registry 登记名 |
|---|---|---|---|---|
| (示例) Order | 一次下单的聚合根 | id, status, amount, lines[] | <主库表 / 文件 / 内存> | Order |

字段级约束写在"关键字段"列里（类型、取值范围、是否可空），例如 `amount: 整数分, > 0`。

## 2. 关系图

```text
Order 1 ──── n OrderLine
  │
  └── n Payment (可空)
```

## 3. 不变量（必须可验证）

每条不变量都要能写成断言或校验函数，并指明校验位置；写不出校验位置的规则等于没有规则。

| 编号 | 不变量 | 校验位置 |
|---|---|---|
| INV-1 | (示例) 订单金额 = 所有行金额之和 | 领域层校验函数 + 单元测试 |
| INV-2 | (示例) 已支付的订单不可回退到待支付状态 | 状态转移表 |

## 4. 迁移与兼容

- 加字段：给默认值，老数据可读；写清默认值语义。
- 删/改字段：属于破坏性变更 → 先写 ADR，再"加新字段 → 双写 → 迁移数据 → 删旧字段"。
- 每次迁移必须能在本地与预发环境重跑；迁移脚本与回滚方式记录在 `{{docsDir}}/runbooks/local-dev.md`。

## 5. 变更流程

1. 写 ADR，说明影响面与迁移路径（触发条件见 `AGENTS.md`）。
2. 改本文件与 `{{aiDir}}/registry.json`（同一条实体两处都要更新，name 保持一致）。
3. 补/改不变量校验与测试。
4. 跑 `node {{aiDir}}/bin/ai-arch.mjs review --impact <改动的文件>` 核对受影响文件。
5. 更新索引：`node {{aiDir}}/bin/ai-arch.mjs index`。
