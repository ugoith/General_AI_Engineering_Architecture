# 接口与契约

> 用途：登记"谁向谁承诺了什么"。改契约前先查这里，改完必须回来更新这里。
> 范围：对外 API、跨模块接口、事件/消息、CLI 参数、文件格式。

## 1. 契约清单

| 契约 | 类型 | 提供方 | 消费方 | 版本/兼容策略 | 契约测试位置 |
|---|---|---|---|---|---|
| (示例) POST /orders | HTTP API | <module-a> | 前端、第三方 | v1，只加不改 | `{{testsDir}}/contract/orders.test` |
| (示例) OrderCreated | 事件 | <module-a> | <module-b> | 字段只增不删 | `{{testsDir}}/contract/events.test` |
| (示例) --output json | CLI | <cli> | 运维脚本 | 字段只增不删 | `{{testsDir}}/contract/cli.test` |

## 2. 单个契约怎么写

```text
契约名：<名称>
请求：字段 | 类型 | 必填 | 约束 | 示例
响应：字段 | 类型 | 必填 | 约束 | 示例
错误：错误码 | 含义 | 触发条件 | 调用方应做什么
幂等：是否幂等；重试语义
超时：调用方期望的超时与重试次数
```

四项缺一不可：字段表、错误码、幂等性、超时语义。缺失的按 `ASSUMPTION:` 标注并尽快确认。

## 3. 错误码约定

| 错误码 | 含义 | 触发条件 | 调用方应做什么 |
|---|---|---|---|
| (示例) INVALID_INPUT | 参数不合法 | 必填缺失或越界 | 修正参数后重试，不要重试原样请求 |
| (示例) NOT_FOUND | 目标不存在 | id 无效或已删除 | 提示用户，不要自动重试 |
| (示例) CONFLICT | 状态冲突 | 并发修改或状态机不允许 | 重新读取最新状态后再决定 |

## 4. 兼容性规则

| 变更 | 是否兼容 | 要求 |
|---|---|---|
| 新增可选字段 | 兼容 | 更新本文件与契约测试 |
| 新增必填字段 / 删除字段 / 改字段语义 | 不兼容 | 先写 ADR，提供版本或弃用期，通知全部消费方 |
| 新增枚举值 | 需确认 | 消费方必须能容忍未知值，否则视为不兼容 |
| 改错误码或错误语义 | 通常不兼容 | 按不兼容处理 |

## 5. 变更流程

1. 在契约清单里找到该契约，确认消费方名单。
2. 不兼容变更：先写 ADR（`{{aiDir}}/decisions/`）→ 加新版本或新字段 → 更新契约测试 → 通知消费方 → 到期删除旧版本。
3. 更新本文件 + `{{aiDir}}/registry.json` + 索引（`node {{aiDir}}/bin/ai-arch.mjs index`）。
4. 在任务包"证据"里贴出契约测试的真实输出。

反例：直接改响应字段名再"顺手"改调用方 —— 外部消费方不会被你顺手改到，属于静默破坏。
