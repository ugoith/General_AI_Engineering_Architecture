# {{testsDir}} — 测试策略与目录

> Web 游戏的测试价值集中在**纯逻辑**上：数值、状态机、存档序列化、关卡数据校验。
> 渲染与触摸交互靠少量端到端冒烟 + 人工验证，不要试图为像素写断言。
> 测试框架先选型并写 ADR（示例命令见下），本文件定义层次与写法要求。

## 1. 先选框架（一次决定，写 ADR）

| 候选 | 适用 | 代价 |
|---|---|---|
| Vitest | Vite 项目（默认推荐）；TS 开箱可用，支持浏览器模式 | 需要 jsdom/浏览器环境来测 DOM 相关代码 |
| Jest | 已有生态沉淀、团队熟悉 | 需要额外 TS/ESM 配置，构建链更重 |
| node:test + tsx | 零依赖倾向的小项目 | 断言与监听能力弱，浏览器 API 需自行 stub |
| Playwright | 端到端：真实浏览器、触摸事件、首屏体积与帧时间测量 | 运行慢，属于 CI 重资产 |

选定后：把命令写入 `.ai/constitution.md` 第 4 节，把依赖写入第 3 节（开发依赖），并写一条 ADR。

## 2. 测试层次

| 层 | 测什么 | 放哪 | 运行成本 |
|---|---|---|---|
| L1 单元 | 纯函数与状态机：伤害计算、碰撞判定、关卡数据校验、存档迁移 | `{{testsDir}}/unit/` | 毫秒级 |
| L2 系统集成 | 系统间协作：输入 → 动作状态、加载器 → 资源可用、存档读写往返 | `{{testsDir}}/systems/` | 毫秒到秒级 |
| L3 端到端 | 真实浏览器：首屏能启动、主流程可玩、触摸事件生效 | `{{testsDir}}/e2e/` | 秒到分钟级 |

规则：**L1 优先且必须占多数**。若某段逻辑难以做 L1，说明它和浏览器 API 耦合过紧，应把纯逻辑抽出来。

## 3. 目录与命名

```
{{testsDir}}/
  unit/          <模块>.test.ts            用例名：<行为>_<条件>_<期望>
  systems/       <系统>.integration.test.ts
  e2e/           <流程>.e2e.ts
  fixtures/      测试用数据（关卡 JSON、存档样本），不要引用真实资源大文件
```

命名示例：`applies_armor_before_hp_reduction`、`falls_back_to_placeholder_when_texture_missing`，
失败时不看代码也能读懂断言意图。

## 4. 写法要求（Web 游戏专项）

- **时间可控**：不要 `setTimeout`/真实 `requestAnimationFrame` 等待；把时间源注入（`now: () => number`），
  测试里用手动推进的假时钟。帧循环测试直接调用 `game.step(1/60)` 若干次。
- **随机可控**：随机数用注入的 provider 或固定种子；禁止在测试里断言随机结果。
- **浏览器 API 要隔离**：需要 `window`/`document`/`AudioContext` 的代码放在边界文件（见 `{{srcDir}}/systems/README.md`），
  纯逻辑测试不加载这些 API；必须 mock 时只 mock 用到的那几个方法。
- **一个用例一个断言目标**；断言具体数值与状态，不要只断言"没抛异常"。
- **资源加载测试要覆盖失败路径**：清单缺 key、请求 404、解码失败，都必须有对应用例。
- 每个用例结束后清理（`game.stop()`、注销监听），避免用例互相污染。

## 5. 反模式

| 反模式 | 后果 | 改成 |
|---|---|---|
| 用真实计时器等待动画结束 | 测试慢且不稳定 | 注入时间源 + 手动 step |
| 断言渲染像素/DOM 细节 | 一改视觉就红 | 断言状态与 API 调用 |
| 只测"没崩" | 抓不到回归 | 断言具体数值/状态迁移 |
| e2e 覆盖主流程以外的一切 | CI 变慢、维护成本高 | e2e 只留 3–5 条关键路径 |
| 测试依赖真实网络 | 离线或限流时全红 | 本地 fixture + mock 加载器 |
