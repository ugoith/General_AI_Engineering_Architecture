# 帧循环与系统调度

> 本文是**结构契约**：一帧里先算什么、后算什么、每个阶段允许做什么。
> 改动本文件的调度顺序 = 结构变更 → **先写 ADR**。系统本身的划分见 `{{srcDir}}/systems/README.md`。

## 1. 一帧的结构

```
驱动源：requestAnimationFrame（或 {{engine}} 自己的 tick 回调）
  │
  ├─ 采样真实 delta → 钳制到 MAX_FRAME_DELTA_SECONDS（切标签页回来时 delta 可能是几十秒）
  ├─ 累加器 += delta；取出 n 个固定步长（n 上限 5，防止追帧雪崩）
  │
  ├─ 阶段 1  fixedUpdate × n   ：物理、状态机、玩法规则（必须可重复、与真实耗时无关）
  ├─ 阶段 2  update    × 1    ：输入采样、动画推进、UI 状态刷新、音频参数
  └─ 阶段 3  render    × 1    ：只读状态并提交绘制；不修改玩法状态
```

骨架实现见 `{{srcDir}}/main.ts` 的 `step()`，一帧上下文对象 `FrameContext` **复用同一实例**（避免每帧分配）。

## 2. 各阶段的允许与禁止

| 阶段 | 允许 | 禁止 |
|---|---|---|
| 采样/钳制 | 读取时间 | 任何分配 |
| `fixedUpdate` | 物理积分、碰撞、AI 决策、数值结算 | 访问 DOM、读写 `localStorage`、发起网络/资源请求、使用真实 delta 做积分 |
| `update` | 读取输入状态、推进动画与计时器、更新 UI 文本（值变化时才写） | 创建/销毁大量对象、读布局属性、长循环 |
| `render` | 提交绘制、更新相机、设置材质/纹理参数 | 修改玩法状态、改输入状态、触发加载 |

三条硬规则：

1. **`render` 只读**。渲染阶段改状态会导致"画面与逻辑不同步"，这类 bug 极难复现。
2. **固定步长内不做 I/O**。加载资源、写存档都要在 `update` 或事件回调里发起，完成后通过状态位通知。
3. **一帧内不等待**。任何 `await` 都必须落在帧循环之外（加载流程用状态机推进）。

## 3. 固定步长 vs 可变步长

| 用固定步长（`fixedUpdate`） | 用可变步长（`update`） |
|---|---|
| 物理积分、碰撞响应、移动 | 相机跟随平滑、UI 动画、粒子表现 |
| 冷却、状态机计时、回合计时 | 音频淡入淡出、屏幕震动 |
| 任何"两次运行结果必须一致"的逻辑 | 任何"看起来顺滑就行"的表现 |

理由：

- 固定步长让玩法与帧率解耦（60Hz 与 144Hz 设备上行为一致），也让**测试可复现**（连续 `step(1/60)` 即可）。
- 表现层用可变步长才能避免高刷新率设备上的抖动。
- 表现层需要"两个逻辑帧之间"的插值：保存上一逻辑帧状态与本帧状态，用累加器比例插值。
  插值只影响显示，**不参与玩法计算**。

## 4. 调度顺序为什么是这样

| 顺序 | 原因 |
|---|---|
| 输入最先在 `update` 采样，逻辑在下一帧 `fixedUpdate` 生效 | 避免输入到达时间影响同一帧内的物理结果（确定性） |
| `level` 在 `audio`/`render` 之前 | 关卡加载/卸载决定了本帧有哪些实体可渲染 |
| `render` 最后 | 它只读；放最后能保证本帧状态已全部更新 |
| `save` 不占位次 | 它是被调用的服务，不参与每帧调度（写存档放在里程碑事件上） |

调整顺序时必须回答：这个系统读谁写的状态？把它提前/推后会不会让某系统读到半更新的状态？

## 5. 帧时间观测与目标

| 指标 | 目标 | 怎么测 |
|---|---|---|
| 单帧总耗时 | 中端机 `≤16.6 ms`（60 FPS） | 浏览器 Performance 面板录制 10 秒游戏过程，看每帧的 Scripting + Rendering |
| 脚本耗时 P95 | `≤8 ms` | Performance → 长任务与函数调用树 |
| 单帧堆分配 | `0`（稳态） | Performance 的 Memory 采样；分配尖峰会触发 GC 掉帧 |
| 掉帧（>33 ms 的帧） | 10 秒内 `0–1` 次 | Performance 的 Frames 轨道 |

超标时的处理顺序（不要跳步）：

1. 先定位是 **脚本**、**渲染** 还是 **布局/样式**；
2. 脚本 → 查每帧分配与遍历；渲染 → 查绘制调用与纹理切换；布局 → 查是否在帧内读写 DOM；
3. 改动后重新取同样长度的数据，**前后对比写进任务包**（没有前后数据的优化不算完成）。

## 6. 页面生命周期

| 事件 | 必须做 |
|---|---|
| `visibilitychange` → 隐藏 | 暂停帧循环；暂停音频；停止计时类玩法逻辑（避免回来时"跳了一大段"） |
| `visibilitychange` → 可见 | 重置时间基准（丢弃隐藏期间的时间），恢复循环；不做"补帧" |
| `blur` | 视为暂停输入：清空按键状态（否则按键会卡住） |
| `beforeunload` | 提示未保存进度；做最后一次设置落盘 |
| 窗口尺寸变化 | 重算画布尺寸与缩放（做防抖）；重算后**不要**在帧内反复测量 |
