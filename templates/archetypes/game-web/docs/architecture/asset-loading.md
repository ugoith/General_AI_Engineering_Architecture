# 资源加载与清单

> Web 游戏的资源问题有三个后果：首屏慢（体积）、玩到一半卡（同步加载）、玩到一半崩（加载失败未处理）。
> 本文用"清单 + 加载器 + 回退 + 预算"四件事解决它们。资源目录约定见 `{{srcDir}}/systems/README.md`。

## 1. 铁律

1. **所有资源必须走统一加载器**，按 key 获取。禁止散落的 `new Image()`、`fetch()`、`import './x.png'`。
2. **每个资源都有失败回退**：占位图 / 静音 / 空数据，并且**记录一次错误日志**（不要静默吞掉）。
3. **清单是唯一事实来源**：新增资源必须进清单（类型、体积、是否首屏必需），否则不算完成。
4. **首屏只加载首屏必需的**：其余资源按场景/关卡延迟加载。
5. **加载是异步的、帧外的**：加载进度用状态机推进，不在帧循环里 `await`。

## 2. 清单格式（`{{srcDir}}/assets/manifest.ts` 或 `.json`）

字段约定：

| 字段 | 含义 | 必填 |
|---|---|---|
| `key` | 代码里引用的唯一标识（kebab-case） | 是 |
| `url` | 资源路径（`public/assets/` 下，构建后原样拷贝） | 是 |
| `type` | `image` / `audio` / `json` / `atlas` / `font` | 是 |
| `bytes` | 实测体积（字节）；用于预算核算 | 是 |
| `preload` | 是否首屏加载（`true` 会直接影响首屏时间，慎用） | 是 |
| `fallback` | 失败时的替代 key 或内置占位（如 `builtin:missing-texture`） | 是 |
| `tags` | 归属场景/关卡，用于按需加载与释放 | 否 |

清单条目示例（结构示意，不是可直接运行的代码）：

| key | url | type | bytes | preload | fallback |
|---|---|---|---|---|---|
| `player-idle` | `assets/sprites/player_idle.webp` | image | 18432 | true | `builtin:missing-texture` |
| `bgm-title` | `assets/audio/title.ogg` | audio | 524288 | false | `builtin:silence` |
| `level-01` | `assets/data/level-01.json` | json | 3072 | false | （无回退，缺失则报错并返回主菜单） |

## 3. 加载流程

```
启动
  → 读取清单（若清单本身是文件，先内联进首屏包，避免多一次请求）
  → 过滤 preload=true 的条目 → 并行加载（并发上限 6，避免占满连接）
  → 每个条目：成功 → 存入资源池；失败 → 使用 fallback + 记录错误（不阻断其它资源）
  → 首屏必需的条目若失败且无回退 → 展示明确错误界面（不要白屏）
  → 进度 = 已完成字节 / 总字节 → 用于真实进度条
  → 全部完成后进入场景
```

延迟加载：

- 关卡/场景切换前按 `tags` 加载该关卡的资源，**加载期间显示进度并允许取消**（取消要真的中断请求）。
- 离开关卡时释放该关卡独占的资源（图片解码后的位图、音频缓冲），清单里标 `shared: true` 的不释放。

## 4. 失败回退策略

| 资源类型 | 回退 | 日志级别 |
|---|---|---|
| 图片/图集 | 内置占位图（纯色 + 棋盘格），玩法照常进行 | warn（附 key 与 url） |
| 音频 | 静音占位；不要抛异常中断流程 | warn |
| 关卡数据/配置 | **无回退**：报错并退回安全场景（主菜单），提示"内容加载失败" | error |
| 字体 | 系统字体栈兜底 | warn（字体缺失会导致文本宽度变化，需检查排版） |

规则：**回退必须是"可玩"的**。一个资源缺失不应该让玩家卡在加载页。

## 5. 体积与格式

| 类型 | 建议 | 原因 |
|---|---|---|
| 位图 | WebP（兼容性不足时 PNG 兜底）；按显示尺寸的 2 倍导出 | 体积与清晰度平衡 |
| 图集 | 合并同屏同时出现的贴图，单张 ≤2048² | 减少绘制调用与请求数 |
| 音频 | 音效用短小的压缩格式（`.ogg`/`.webm`），音乐流式播放 | 解码内存与首屏体积 |
| 数据 | JSON 压缩（构建时 gzip/brotli 由服务器或打包器处理） | 网络传输 |
| 字体 | 只保留用到的字符子集 | 中文字体全量可达数 MB |

体积核算规则：

- 清单里的 `bytes` 是**实测值**，不是估计值；新增资源后在任务包里记录首屏体积增量。
- 首屏体积预算见 `.ai/constitution.md` 第 5 节；**超预算的改动必须写 ADR 或改为延迟加载**。
- 构建输出（`dist/`）里的体积报告是唯一权威；手算的数字不算证据。

## 6. 缓存与版本

- 静态资源使用**带内容 hash 的文件名**（构建产物默认行为），避免玩家拿到旧版本。
- `index.html` **不要**长缓存（否则更新不生效）；资源可以长缓存（内容变化会换文件名）。
- 存档（`localStorage`/`IndexedDB`）带 `version` 字段：读取时版本不符 → 走迁移函数或提示重置，**不要静默丢弃玩家进度**。

## 7. 反模式

| 反模式 | 后果 | 改成 |
|---|---|---|
| 在系统代码里 `new Image()` | 无回退、无预算、无进度 | 走加载器 + 清单 |
| 首屏 preload 一切 | 首屏时间爆炸 | 只 preload 首屏必需，其余按标签延迟 |
| 加载失败 `catch` 后什么都不做 | 玩家看到黑屏/空关卡 | 回退 + 日志 + 可玩性保障 |
| 关卡资源不释放 | 内存持续上涨，切几个关卡后崩溃 | 按 `tags` 释放，`shared` 标记共享资源 |
| 用假进度条 | 体验差且掩盖真实问题 | 用"已完成字节/总字节"的真实进度 |
| 直接 `import sprite from './a.png'` | 体积不受清单管控、无法延迟加载 | 放进 `public/assets/` 并登记清单 |
