# 性能与体积预算

> 预算不是愿望，是**判定标准**：超标就要处理，处理要么改实现，要么走 ADR 改预算。
> 数字必须来自实测基线；本文件的表格与 `.ai/constitution.md` 第 5 节必须一致。

## 1. 预算表（基线待实测填写）

| 指标 | 预算 | 测量方式 | 超标处理 |
|---|---|---|---|
| 帧时间 | `≤16.6 ms`（60 FPS） | Performance 录制 10 s，看 Frames 轨道 | 定位到系统 → 改 → 重新取数 |
| 帧时间抖动 P95 | `≤20 ms` | 同上，统计长帧 | 查 GC 与一次性大任务 |
| 脚本耗时 | `≤8 ms/帧` | Performance → Bottom-Up | 查每帧遍历与分配 |
| 单帧堆分配 | `0`（稳态） | Performance → Memory | 对象池 / 复用容器 / 去掉字符串拼接 |
| 绘制调用 | 待填写：例如 `≤150` | 引擎调试面板（Phaser/Pixi/Three 均有 draw call 计数） | 合批、图集、减少材质切换 |
| 首屏 JS（gzip） | 待填写：例如 `≤1.5 MB` | 构建输出报告 | 延迟加载非首屏模块；评估依赖 |
| 首屏资源总量 | 待填写 | 清单 `bytes` 求和（preload 项） | 降低分辨率/换格式/改延迟加载 |
| 首屏可交互 | 待填写：例如 `≤3 s`（4G 中端机） | 真机 + 网络限速 | 减少首屏依赖链 |
| 内存占用 | 待填写：例如 `≤300 MB` | 浏览器任务管理器 / Performance Memory | 释放关卡资源、降纹理尺寸 |

## 2. 测量基线怎么建（只做一次，之后对比用）

1. 选一台**目标中端设备**（或开发者工具里限速到中端水平：CPU 4x slowdown + Fast 3G）。
2. 固定场景与操作脚本：启动 → 进入某一关卡 → 执行固定操作 10 秒 → 结束。
3. 记录：帧时间分布（平均/P95）、脚本耗时、绘制调用峰值、首屏 JS 体积、可交互时间。
4. 把数字写进第 1 节表格与宪法第 5 节，并记在一条 ADR 里（作为"当时的基线"）。
5. **之后每次性能相关改动都用同一套流程取数**，否则前后不可比。

## 3. 常见瓶颈与处理顺序

| 症状 | 先查 | 常见根因 | 处理 |
|---|---|---|---|
| 稳定低于 60 FPS | 渲染还是脚本 | 绘制调用过多 / 每帧全量遍历 | 合批与图集；把遍历改成事件驱动 |
| 周期性卡顿（每几秒一次） | Memory 采样 | GC：每帧分配 | 消除帧内分配（对象池、复用数组、避免字符串） |
| 首次进关卡卡一下 | Network + Scripting | 同步加载资源、解析大 JSON | 延迟加载 + 分帧解析 |
| 移动端比桌面差很多 | Device 限速后的脚本耗时 | 触摸事件处理过重、分辨率过高 | 降低渲染分辨率；触摸事件节流 |
| 切后台回来"跳帧" | 帧循环的 delta 处理 | 未钳制 delta / 未暂停 | 钳制 delta + `visibilitychange` 暂停 |
| 内存持续上涨 | Memory 时间线 | 关卡资源未释放、事件监听未注销 | 按标签释放资源；`dispose` 里注销监听 |
| 首屏慢 | Network 瀑布 | preload 过多、依赖链过长 | 缩短关键路径；非必需资源延后 |

## 4. 帧内零分配的写法对照

| 反模式 | 每帧代价 | 正确写法 |
|---|---|---|
| `const v = { x: 0, y: 0 }` | 每帧一个对象 | 模块级复用对象 `const tmp = { x: 0, y: 0 }` |
| `entities.filter(e => e.alive)` | 每帧一个新数组 | 原地压缩（写指针覆盖）或维护活跃列表 |
| `` `hp: ${hp}` `` | 每帧字符串 | 值变化时才更新文本，缓存上次文本 |
| 每帧 `new Vector2(...)` | 对象churn | 复用向量或用两个 number 字段 |
| 闭包捕获：`arr.forEach(x => f(x))` | 每帧一个闭包 | 普通 `for` 循环 |
| 每帧 `JSON.parse/stringify` | 巨大开销 | 只在事件点做序列化 |
| 每帧 `console.log` | 同步 I/O + 字符串 | 用带开关的调试层，默认关闭 |

## 5. 体积控制清单

- [ ] 每个运行时依赖都在宪法第 3 节，且记录了体积影响。
- [ ] 首屏不加载非首屏资源（清单 `preload` 只标必需项）。
- [ ] 图片使用 WebP 或按显示尺寸导出；图集单张 ≤2048²。
- [ ] 音频按用途选择格式与是否流式。
- [ ] 中文/多语言字体做了子集化。
- [ ] 构建输出里没有误入的开发资源（测试图、调试关卡、sourcemap 未发布）。

## 6. 什么时候允许改预算

只有三种情况，且都必须写 ADR：

1. 玩法/内容需求确实提高（例如新增 3D 场景导致绘制调用上升）；
2. 目标设备档发生变化（例如从桌面扩展到低端 Android）；
3. 实测发现原预算与真实设备能力不符（附实测数据）。

**不允许**因为"改起来麻烦"改预算；也不允许用"降画质/降分辨率"代替定位根因。
