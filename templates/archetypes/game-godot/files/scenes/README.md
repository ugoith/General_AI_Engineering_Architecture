# scenes/ — 场景目录约定

Godot 里**场景就是组件**：可复用、可嵌套、可继承。本文件定义"什么该做成场景、放在哪、怎么复用"。
场景的索引与细读方式见 `{{aiDir}}/index/asset-index.md`，场景间流程见 `{{docsDir}}/architecture/scene-composition.md`。

## 1. 目录结构

```
scenes/
  Main.tscn             主场景（project.godot 的 run/main_scene 指向它）
  level/                关卡与关卡级流程（Level01.tscn、LevelRoot 等）
  actors/               可复用 Actor：Player、Enemy_*、Pickup_*
  ui/                   UI 场景：HUD、菜单、对话框（尽量做成可独立运行的场景）
  systems/              非可视系统场景（音频管理、存档、生成器）
  dev/                  开发验证用最小复现场景（命名 Dev_<功能>.tscn）
```

放置规则：

- **一个场景一个职责**。`Level01.tscn` 不应包含 HUD 的节点树，而应实例化 `ui/HUD.tscn`。
- **UI 场景必须能单独按 F6 运行**（不依赖关卡）：用 `@export` 注入数据，不要直接访问父级玩法节点。
- **actors/ 下的场景必须自洽**：自己的脚本、自己的碰撞、自己的动画；不要在关卡里"补上它缺的组件"。
- 开发验证场景放 `dev/`，功能稳定后删除或转正；**不要留在关卡目录里**。

## 2. 什么该做成场景，什么该做成脚本

| 该做成场景 | 该做成脚本 / 资源 |
|---|---|
| 有节点树与可视元素的对象（角色、UI、道具） | 纯逻辑（伤害计算、状态机、数据转换） |
| 需要在编辑器里摆放与调整的对象 | 需要在多处复用的算法 |
| 会被多处实例化的组合（HUD、子弹、掉落物） | 配置数据（`.tres` 资源） |
| 关卡与关卡流程 | autoload 服务（见 `autoload-and-signals.md`） |

判断法：**"美术/策划需要在编辑器里摆它吗？"** 需要 → 场景；只是数值与规则 → 脚本 + `.tres` 资源。

## 3. 复用与继承

- **优先实例化（instance）而不是场景继承（inherited scene）**：继承链超过 2 层就很难追踪改动的来源。
  需要变体时：实例化 + `@export` 参数，或 `editable_children` 局部覆盖（覆盖要在索引 `notes` 里写清）。
- 场景入口脚本用 `class_name` 暴露类型，方便其它脚本静态引用（改名 = 契约变更，要写 ADR）。
- **不要在子场景里 `get_node("../../..")` 向上抓父级**。需要外部对象时用 `@export` 引用或让父级调用子场景的公开方法。
- 跨场景通信一律走信号或 `@export` 注入，禁止靠节点路径硬编码"找"过去。

## 4. 节点命名与结构约定

| 约定 | 说明 |
|---|---|
| 入口节点名稳定 | 如 `Systems/GameRoot`、`UI/HUD`；改名必须同步索引与引用方 |
| 类型前缀 | `Systems/`（逻辑系统）、`UI/`（界面容器）、`World/`（关卡内容容器），避免几十个平级节点 |
| 每个场景根节点挂**一个**脚本 | 根脚本负责编排，子节点脚本负责局部行为 |
| `@onready var` 集中放在脚本顶部 | 便于一次性看出这个脚本依赖哪些节点 |
| 用 `%UniqueName`（场景唯一名）访问关键节点 | 结构调整时不易断链，但要保证唯一名确实唯一 |

## 5. 反模式

| 反模式 | 后果 | 改成 |
|---|---|---|
| 把所有东西塞进 `Main.tscn` | 改一处要重载全部，协作冲突巨大 | 拆成 `level/`+`actors/`+`ui/` 场景组合 |
| UI 场景直接访问关卡节点 | UI 无法独立运行与测试 | `@export` 注入数据 + 信号上报 |
| 用节点路径字符串跨场景查找 | 改名静默失效 | `@export` 引用 / autoload 服务 / 信号 |
| 场景继承 3 层以上 | 改父场景影响面不可预测 | 实例化 + 参数化 |
| 在 `_ready` 之前访问子节点 | 报 null | `@onready` 或 `_ready` 中访问 |
| 用 `_process` 轮询状态变化 | 浪费 CPU、逻辑分散 | 用信号驱动 |

## 6. 提交前检查（场景改动）

- [ ] 索引条目已更新（`entrypoints`/`attachedScripts`/`deps`/`risk`/`hash`）。
- [ ] 新场景能单独按 F6 运行（UI 与 actors 尤其重要）。
- [ ] 没有新增节点路径字符串硬编码。
- [ ] `dev/` 下没有留下该删除的临时场景。
- [ ] 跑过 L0 无头导入校验（`godot --headless --path . --quit`）。
