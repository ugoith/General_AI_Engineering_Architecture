# tests/ — 测试策略与目录

> Godot 没有内置测试运行器，**测试框架必须由项目选定并写 ADR**（引入 `addons/` 属于依赖变更）。
> 本文件定义测试的层次、放哪、怎么写才算有价值。无头运行命令见 `{{docsDir}}/runbooks/build-and-verify.md`。

## 1. 先选框架（一次决定，写 ADR）

| 候选 | 适用 | 代价 |
|---|---|---|
| GUT（Godot Unit Test，`addons/gut/`） | GDScript 项目、需要断言/参数化/无头运行 | 引入第三方插件，需要随引擎版本升级 |
| GdUnit4（`addons/gdUnit4/`） | 需要场景测试、Mock、与 IDE 集成 | 同上，功能多但更重 |
| 自建 `SceneTree` 脚本 | 极小项目、只做冒烟 | 无断言库、可读性差，超过 10 个用例就该换框架 |
| C# 项目的 NUnit/xUnit | .NET 版 Godot | 需要解决引擎 API 在无头环境的初始化 |

选定后：写入 `.ai/constitution.md` 第 3 节（已批准依赖）+ 第 4 节（真实运行命令）+ 一条 ADR。

## 2. 测试层次（成本从低到高）

| 层 | 测什么 | 放哪 | 运行成本 |
|---|---|---|---|
| L0 冒烟 | 关键资源存在、autoload 已注册、脚本可解析 | `scripts/dev/smoke_check.gd` | 秒级，无头 |
| L1 单元 | 纯逻辑：伤害计算、数值转换、状态机转移、存档序列化 | `tests/unit/` | 秒级，无头，不需要场景 |
| L2 场景/集成 | 节点行为：信号是否按预期发出、UI 响应、Actor 交互 | `tests/scene/` | 秒到分钟级，需要实例化场景 |
| L3 端到端 | 从主场景走到某个里程碑（如"进入关卡并击败一个敌人"） | `tests/e2e/` | 分钟级，脆弱，只保留少数关键路径 |

规则：**L1 优先**。纯逻辑不该依赖节点树——如果一段逻辑难以做 L1 测试，说明它和节点耦合过紧，应该拆出来。

## 3. 目录与命名

```
tests/
  unit/           test_<被测对象>.gd      用例名 test_<行为>_<条件>_<期望>
  scene/          test_<场景名>.gd
  e2e/            test_<流程>.gd
  fixtures/       测试用资源与场景（不要引用正式关卡）
```

命名示例：`test_damage_applies_armor_before_hp_reduction`（说清条件与期望，失败时不看代码也能读懂）。

## 4. 写法要求

- **一个用例只断言一件事**；多个断言必须都指向同一行为。
- **不依赖真实时间**：不用 `await create_timer(0.5)` 这类等待；改用显式推进或注入的时间源。
- **不依赖编辑器状态**：测试必须在 `--headless` 下可运行，不弹窗、不依赖选中节点。
- **每个用例自建对象并在结束释放**（`queue_free()` / `free()`），避免用例间互相污染。
- **fixtures 用最小场景**：不要拿正式关卡做测试夹具（它会随玩法变化而破坏测试）。
- 随机性（掉落、暴击）必须可注入种子，测试里固定种子。

## 5. 反模式

| 反模式 | 后果 | 改成 |
|---|---|---|
| 测试里加载正式关卡 | 关卡一变测试全红 | 用 `tests/fixtures/` 的最小场景 |
| 用 `await` 真实计时器同步 | 无头环境慢且不稳定 | 显式驱动 `_process` 或用可注入时钟 |
| 只测"没崩溃" | 回归抓不到 | 断言具体数值/信号/状态 |
| 断言私有实现细节 | 一重构就红 | 断言公开行为与信号 |
| 把测试写成"打印结果让人看" | 无法自动判定 | 用框架断言，失败退出码非 0 |
