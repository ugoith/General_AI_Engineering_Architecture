# autoload 与信号（全局状态的使用规则）

> autoload 与信号是 Godot 最强的两把工具，也是最容易把项目变成"隐式全局状态泥潭"的两把工具。
> 本文给出清单、允许的用法、以及**什么时候禁止用全局信号**。

## 1. autoload 清单（改这里必须写 ADR）

| 单例名 | 脚本 | 职责（一个） | 依赖 | 生命周期 |
|---|---|---|---|---|
| `Game` | `res://scripts/autoload/game.gd`（C# 项目为 `Game.cs`） | 流程切换、存档/设置读写 | 无 | 全程 |

规则：

- **一个 autoload 一个职责**。出现"EventBus + Config + Save"三合一的 autoload 就是设计错误，拆开。
- autoload 之间**不允许互相调用成一团**；确有依赖时按依赖方向排列注册顺序，并在本表记录。
- autoload 不持有场景节点引用（场景会被释放），需要交互时发信号或让场景主动注册。
- 新增 autoload 的流程：写 ADR（为什么需要全局）→ 在 `project.godot` 的 `[autoload]` 注册 → 更新本表 → 更新 asset-index。
- 删除 autoload 同样要 ADR（说明状态迁移到哪里）。

## 2. 什么该是 autoload，什么不该

| 该做 autoload | 不该做 autoload |
|---|---|
| 进程级唯一且跨场景存活的服务（音频总线、场景流程、设置、存档入口） | 某关卡的玩法逻辑、某个 UI 的状态 |
| 需要在多个场景启动前就绪的东西（资源预加载清单） | 只是"想在任何地方都能访问"的便利对象 |
| 包装平台差异（存档路径、语言、平台特性） | 数据表（应做成 `.tres` 资源） |

判定法：**"它在任何场景里都必须存在吗？"** 不是 → 不要做 autoload，用场景节点或资源。

## 3. 信号的正确用法

### 局部（父子、同场景内）

- **直接调用**公开方法优于信号：显式、可静态检查、易调试。
- 需要解耦时（子节点不该知道父节点的类型）用信号：子节点 `signal hit_taken(damage: int)`，父节点连接处理。
- 连接写在哪里要固定：**同一场景内由父节点在 `_ready` 连接子节点信号**，便于一眼看到全部连接关系。
- 断开：跨场景/跨生命周期的连接必须在 `_exit_tree` 断开，或用 `CONNECT_ONE_SHOT`。

### 命名与载荷

| 约定 | 说明 |
|---|---|
| 信号名用"已发生的事实" | `health_changed`、`level_completed`，不用 `do_damage` 这类命令式命名 |
| 载荷用类型化参数 | `signal health_changed(current: int, max_value: int)`；不要传 Dictionary 让接收方猜字段 |
| 载荷是契约 | 改参数 = 数据契约变更 → **写 ADR** 并更新所有订阅者（`files.json` 的 `imports`） |
| 不传递节点以外的重对象 | 传 ID 或值，别把整个场景/存档字典广播出去 |

## 4. 何时**禁止**全局信号（信号总线）

**默认禁止**引入全局信号总线（例如一个 `EventBus` autoload 里塞几十个信号）。理由：它把"谁触发、谁响应"变成不可追踪的隐式关系，测试与调试成本急剧上升。

允许的例外（必须同时满足，否则不批）：

1. 事件确实**跨多个不相关模块**，且发送方不可能持有接收方引用（例如"成就系统"需要知道多个模块的里程碑）；
2. 事件名与载荷已在本节表格登记（名称、载荷、发送方、订阅方）；
3. 在 ADR 中记录了采用理由与替代方案（为什么不用显式引用/服务方法）；
4. 订阅方数量可控（超过 5 个订阅者时先怀疑设计）。

即使允许，也必须遵守：

- 总线只做**转发**，不含逻辑、不改数据、不回发。
- 每个信号的"发送方 / 订阅方 / 载荷"必须在本文件登记，代码评审时对照。
- 载荷变更走 ADR。
- 禁止用总线传"命令"（`request_spawn_enemy`），只传"已发生的事实"。

## 5. 常见错误

| 错误 | 症状 | 修法 |
|---|---|---|
| 用 autoload 存"当前玩家"等场景对象 | 场景切换后引用失效/内存泄漏 | 只存 ID 或值；场景对象由场景持有 |
| 信号连接写在子节点里连父节点 | 子场景无法独立运行 | 由父节点统一连接 |
| 信号名是命令式（`do_attack`） | 语义混乱、出现回环 | 改成事实式命名，命令走方法调用 |
| 一个信号被 10 处连接 | 改一处行为牵动全局 | 收敛为 1–2 个明确订阅方，其余走局部调用 |
| 忘记断开导致重复触发 | 同一事件处理多次 | 在 `_exit_tree` 断开或 `CONNECT_ONE_SHOT` |
| 用信号传大字典 | 契约模糊、易漏改 | 类型化参数或专门的 Result 类 |
