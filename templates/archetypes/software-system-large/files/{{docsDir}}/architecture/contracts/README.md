# 契约清单与版本策略（L 级）

> 契约 = 你向别人承诺的东西：对外 API、跨模块接口、事件载荷、CLI 参数、文件格式、数据结构。
> L 级要求：**每个契约都有版本、有 owner、有契约测试、有弃用流程**。没有版本策略的契约，改一次就会静默破坏消费方。

## 1. 契约清单

| 契约 | 类型 | 提供方（owner） | 消费方 | 当前版本 | 兼容策略 | 契约测试 | 字段文档 |
|---|---|---|---|---|---|---|---|
| (示例) POST /orders | HTTP API | <module-a> / <@team> | 前端、第三方 | v1 | 只增不改，破坏性变更走 v2 | `{{testsDir}}/contract/orders/` | `{{docsDir}}/architecture/interfaces.md` |
| (示例) OrderCreated | 事件 | <module-a> / <@team> | <module-b> | v1 | 字段只增不删，消费方容忍未知字段 | `{{testsDir}}/contract/events/` | 同上 |
| (示例) --output json | CLI | <cli> / <@team> | 运维脚本 | v1 | 字段只增不删 | `{{testsDir}}/contract/cli/` | 同上 |
| (示例) orders.parquet | 文件格式 | <module-c> / <@team> | 数据团队 | v2 | 保留 v1 读取器直到弃用期结束 | `{{testsDir}}/contract/files/` | 同上 |

每条契约必须有 owner；没有 owner 的契约等于没有契约，先在评审里指定。

## 2. 版本策略

- 版本号用 `v1`、`v2` 这种单调递增整数（不用语义化三段式，契约只关心"兼容 / 不兼容"）。
- 兼容性判定见第 3 节；判定为不兼容时**新开一个版本**，不要原地改。
- 弃用流程（缺一不可）：
  1. **公告**：在 `{{aiDir}}/decisions/` 写 ADR，说明原因、影响面、迁移方式、弃用截止时间。
  2. **并存**：新旧版本同时可用；旧版本只修安全与严重缺陷，不再加功能。
  3. **弃用期**：默认不短于一个完整发布周期且不少于 30 天（项目可在 ADR 中调整，但必须有数字）。
  4. **通知**：逐个通知第 1 节表里的消费方，并在发布说明中记录。
  5. **删除**：到期且消费方已迁移后删除旧版本，更新本文件与 `{{docsDir}}/architecture/interfaces.md`。
- 谁批准：提供方 owner 提议 + 消费方确认 + 一条 ADR；跨团队契约不接受"先上线再通知"。

## 3. 兼容性判定

| 变更 | 判定 | 要求 |
|---|---|---|
| 新增可选字段 / 新增可选参数 | 兼容 | 更新契约测试 |
| 新增枚举值 | 需确认 | 消费方必须能容忍未知值，否则按不兼容处理 |
| 新增必填字段、删除字段、改字段含义或单位 | 不兼容 | 新版本 + 弃用期 + ADR |
| 收窄取值范围、收紧校验 | 不兼容 | 同上 |
| 改错误码 / 改错误语义 | 通常不兼容 | 按不兼容处理 |
| 改超时、重试、幂等语义 | 不兼容（语义级） | 必须写进契约文档并通知消费方 |

## 4. 契约测试要求

- 每个契约至少一条契约测试，落在 `{{testsDir}}/contract/` 下，与实现同仓库。
- 测试内容至少覆盖：字段存在性与类型、错误码、幂等行为、超时/失败路径。
- CI 必须跑契约测试；契约测试失败等同构建失败，不允许跳过。
- 契约测试是"消费方视角"的测试：站在调用方断言，而不是断言内部实现。

## 5. 变更流程

1. 查第 1 节找到该契约的 owner 与消费方。
2. 按第 3 节判定兼容性；不兼容则先写 ADR 并确定弃用期。
3. 改实现 + 改契约测试 + 更新 `{{docsDir}}/architecture/interfaces.md` 的字段表。
4. 更新本文件（版本、弃用期）+ `{{aiDir}}/registry.json` + 索引。
5. 跑 `node {{aiDir}}/bin/ai-arch.mjs review --impact <改动文件>`，确认受影响文件与测试都处理了。

## 6. 反例

| 反例 | 为什么坏 |
|---|---|
| 直接改响应字段名，然后"顺手"改了自己这边的调用方 | 外部消费方不会被你顺手改到 |
| 契约只写在代码里，没有字段文档 | 消费方只能读实现猜语义，改一次就崩 |
| 弃用期写成"尽快" | 没有数字的期限等于无限期 |
| 契约测试断言内部实现细节 | 实现一重构测试就红，最后没人敢跑 |
