# 模块与所有权规则（L 级）

> 模块 = **有明确所有者、可独立发布或独立测试、边界可被机器检查**的单元。
> L 级的核心差别：边界不靠口头约定，而靠 CI 里的依赖规则；所有权不靠记忆，而靠本文件与 `{{aiDir}}/registry.json` 的 `owner` 字段。

## 1. 目录与出口

```text
{{srcDir}}/modules/<module>/
  public.<ext>        # 唯一出口：其它模块只能引用这里导出的符号
  ...                 # 内部实现，外部不得引用
{{testsDir}}/modules/<module>/           # 模块自己的单元测试
{{testsDir}}/contract/<contract-name>/   # 契约测试（跨模块、跨团队）
```

## 2. 所有权表（必须与 registry 的 owner 一致）

| 模块 | owner | 公开出口 | 允许依赖 | 拥有哪些数据 | 允许的跨模块方式 |
|---|---|---|---|---|---|
| `<module-a>` | <@team> | `{{srcDir}}/modules/<module-a>/public` | <模块清单> | <实体清单> | 同步调用 / 事件 |

规则：数据所有权与模块所有权必须一一对应——**每个实体只有一个 owner，且只有 owner 能写它**。跨模块读数据要经 owner 的公开接口，不允许直接访问别人的表或存储。

## 3. 硬规则（由 CI 检查，见 dependency-rules）

| 编号 | 规则 | 违反后果 |
|---|---|---|
| R1 | 跨模块只引用 public 出口 | CI 失败，禁止合并 |
| R2 | 依赖方向单向（入口 → 应用 → 领域；基础设施不反向依赖业务） | CI 失败 |
| R3 | 禁止循环依赖 | CI 失败 |
| R4 | 领域层不依赖框架、IO、网络 | CI 失败 |
| R5 | 只有 owner 能写自己的数据；跨模块写操作必须经公开接口 | CI 失败 / 评审阻断 |
| R6 | 共享代码进独立模块，且该模块不得反向依赖任何业务模块 | CI 失败 |

规则的配置、例外与检查命令统一维护在 `{{docsDir}}/architecture/dependency-rules.md`。

## 4. 跨模块协作方式怎么选

| 场景 | 用什么 | 注意 |
|---|---|---|
| 需要立即拿到结果 | 同步调用公开接口 | 必须约定超时与错误码；禁止层层重试 |
| 只是通知，可以延迟 | 事件（进程内或消息） | 事件载荷是契约，必须版本化；消费方要幂等 |
| 需要读别人的数据做展示 | 经 owner 的查询接口或读模型 | 读模型也是契约，同样受版本策略约束 |

## 5. 循环依赖与边界违规

1. 用 `node {{aiDir}}/bin/ai-arch.mjs review --impact <文件>` 查 `importedBy`，确认环的两端。
2. 三选一：下沉共同依赖到第三个模块 / 改为事件或上层编排 / 合并模块。
3. **写 ADR**，说明为什么选它、放弃了什么，并更新 `{{docsDir}}/architecture/overview.md` 与依赖规则。
4. 禁止用延迟导入、全局单例、反射绕过——那只是把问题藏进运行时。

## 6. 新增 / 拆分模块清单

- [ ] 职责与现有模块不重叠；写入 `{{docsDir}}/architecture/overview.md` 的模块表
- [ ] 指定 owner，并写入 `{{aiDir}}/registry.json` 的实体 `owner`
- [ ] 明确它拥有哪些数据；`{{docsDir}}/architecture/data-model.md` 同步数据所有权
- [ ] 在 `{{docsDir}}/architecture/dependency-rules.md` 更新允许的依赖方向
- [ ] 写 ADR（触发条件见 `AGENTS.md`）
- [ ] 补单元测试；跨模块调用补契约测试
- [ ] 更新索引与文档：`node {{aiDir}}/bin/ai-arch.mjs index`

## 7. 反例

| 反例 | 为什么坏 |
|---|---|
| 两个团队往同一个模块里加代码 | 所有权消失，冲突与责任都无人承担 |
| 用"共享库"绕过公共接口 | 共享库会反向依赖业务模块，最终人人依赖它 |
| 跨模块直接读对方的数据表 | 数据所有权失效，schema 变更会静默破坏别的团队 |
| 在评审里默认放过一次违规依赖 | 例外会变成惯例；例外必须进例外表并写明到期条件 |
