# 数据模型与数据所有权（L 级）

> 用途：定义"数据长什么样、归谁所有、怎么演进"。L 级的数据问题几乎都来自**所有权不清**，而不是字段设计不好。
> 硬规则：**每个实体只有一个 owner，且只有 owner 能写它。**

## 1. 数据所有权表

| 实体 | owner（模块 / 团队） | 写入方 | 允许的读取方 | 存储位置 | registry 登记名 |
|---|---|---|---|---|---|
| (示例) Order | <module-a> / <@team> | <module-a> | 经公开查询接口 | <主库 orders 表> | Order |
| (示例) PriceRule | <pricing> / <@team> | <pricing> | <module-a> 经接口读取 | <配置库 / 文件> | PriceRule |

读取方式只允许两种：调用 owner 的公开查询接口，或消费 owner 发布的读模型/事件。**直接查询他人的表属于违规**，会被依赖规则检查与评审阻断。

## 2. 关系图

```text
<module-a>.Order 1 ──── n OrderLine
        │
        └── n Payment        （owner: <module-c>，经事件关联，不做跨库外键）
```

跨模块关系用**标识引用 + 事件**表达，不要跨模块外键或跨库 JOIN：那会把两个模块的发布节奏锁死。

## 3. 实体与字段

| 实体 | 关键字段 | 字段约束 |
|---|---|---|
| (示例) Order | id, status, amount, lines[] | `amount: 整数分且 > 0`；`status` 只能按状态机转移 |

## 4. 不变量

| 编号 | 不变量 | 校验位置 | owner |
|---|---|---|---|
| INV-1 | (示例) 订单金额 = 所有行之和 | 领域校验函数 + 单元测试 | <module-a> |
| INV-2 | (示例) 幂等键在同一租户内唯一 | 写入路径 + 契约测试 | <module-a> |

每条不变量都要有校验位置和 owner；写不出校验位置的规则等于没有规则。

## 5. 版本化与迁移

L 级必须假设"迁移期间新旧代码同时在跑"：

1. **加字段**：先加可空/带默认值 → 双写 → 回填历史数据 → 切读 → 最后清理旧路径。
2. **改语义**：新字段 + 双读校验，确认两边一致后再切；不一致率必须可观测。
3. **删字段**：至少经历一个完整发布周期，且确认无读取方（依赖规则检查 + 日志）。
4. **回滚**：每个迁移都要能在不回滚数据的前提下回滚代码；做不到就要写清"不可回滚"的窗口与应对。
5. 迁移脚本、回填脚本与验证查询记录在 `{{docsDir}}/runbooks/local-dev.md`。

## 6. 变更流程

1. 写 ADR（触发条件见 `AGENTS.md`），说明影响面、迁移路径、不可逆点。
2. 更新本文件（所有权、字段、不变量）与 `{{aiDir}}/registry.json`（同一实体两处 `name` 必须一致）。
3. 更新契约：受影响的接口、事件与读模型 → `{{docsDir}}/architecture/interfaces.md` 与 `{{docsDir}}/architecture/contracts/README.md`。
4. 补不变量校验、迁移测试与契约测试。
5. 跑 `node {{aiDir}}/bin/ai-arch.mjs review --impact <改动文件>`，再跑 `index` 同步索引。
