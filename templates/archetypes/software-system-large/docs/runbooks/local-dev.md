## 3. 环境变量

`.env.example` 是唯一权威清单；新增变量必须同步更新它，否则别人跑不起来。

| 变量 | 必填 | 默认 | 说明 |
|---|---|---|---|
| (示例) `APP_PORT` | 是 | 8080 | 本地监听端口 |
| (示例) `DATABASE_URL` | 是 | 无 | 本地库连接串；不要写真实生产凭据 |
| (示例) `QUEUE_URL` | 否 | 空 | 为空时使用进程内事件实现 |
| (示例) `LOG_LEVEL` | 否 | info | debug 会打印敏感字段，仅本地使用 |

## 6. 常见故障

| 现象 | 可能原因 | 处理 |
|---|---|---|
| 启动报缺少环境变量 | `.env` 未创建或变量名拼错 | 对照 `.env.example` 逐项核对 |
| 契约测试失败但单元测试通过 | 契约被改而未走版本流程 | 查 `{{docsDir}}/architecture/interfaces.md` 的版本矩阵；不要直接改测试断言 |
| 依赖规则检查报违规 | 跨模块引用了内部实现或方向反了 | 见 `{{docsDir}}/architecture/dependency-rules.md` 的违规处理流程 |
| 基准波动很大 | 环境噪声（后台任务、节流） | 增大样本量、取中位数/P95；必要时在专用环境复测 |
| 迁移报状态不一致 | 本地库与迁移历史不同步 | 查迁移历史；必要时重置本地库（仅本地） |
| 事件消费重复处理 | 投递语义是"至少一次" | 检查消费方幂等键实现，而不是关闭重试 |

## 7. 排障原则

1. 先看日志、退出码与追踪 id，再猜原因；关键输出贴进任务包"证据"。
2. 不要用"多加一层重试"掩盖问题：重试与超时语义属于契约，改动要走变更流程。
3. 环境或工具链变更后，必须回写本手册，并重建性能基线（见 `{{docsDir}}/architecture/performance-budget.md`）。
