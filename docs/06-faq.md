# FAQ 与生态对比

## 一、与现有标准/工具的关系

### 和 `AGENTS.md` 是什么关系？

`AGENTS.md` 是[开放标准](https://agents.md)：仓库根目录放一个文件，AI 工具在会话开始时自动加载。本框架**建立在它之上**，并遵守它最关键的经验：**这是指针，不是百科**——`AGENTS.md` 保持 ≤ 150 行，只放硬约束、路由表、提交前检查。

`AGENTS.md` 标准自身明确不覆盖的部分，正是本框架补的：

| `AGENTS.md` 覆盖 | 本框架补充 |
|---|---|
| 项目是什么、约定在哪 | 索引与增量读取机制（避免重复读文件） |
| 约束、非显然注意事项 | 规模分级与设计模式门槛 |
| 指向 `docs/` 的路径 | 规范演进机制（影响矩阵、漂移检测、评审触发） |
| —— | 项目类型模板（7 套 archetype）与 CLI |

### 和 spec-kit / 规格驱动开发（SDD）的区别？

SDD 工具（如 spec-kit 系列）关注**"先写规格再实现"**这一条流水线：需求 → 规格 → 计划 → 任务 → 实现。
本框架关注的是**跨任务的持续成本**：索引、增量读取、规模分级、规范不腐化。两者不冲突：

- 用 SDD 产出能力规格（capability spec）→ 用本框架的 `task` 把规格变成受控的读取清单与预算；
- 把 SDD 的规格文件纳入 `.ai/index/impact-map.json` 的同步更新项。

### 和 `llms.txt` 的区别？

`llms.txt` 是给**外部消费者**（模型去理解你的产品/文档站）用的发现入口。本框架的 `AGENTS.md` + `.ai/` 是给**在仓库里干活的 agent**用的操作上下文。一个对外，一个对内，用途不重叠。

### 和向量库 / RAG 代码检索的区别？

本框架**明确拒绝**用嵌入检索替代索引，理由是：检索结果不可解释、不可 diff、引入依赖与运维成本，且无法回答"我上次读过了，这次要不要再读"。
本框架的答案是落盘的任务包：读什么文件、为什么、hash 是多少、值多少 token——全部可审、可提交、可复现。取舍详见 [`04-design-notes.md`](04-design-notes.md) 第 3 节。

## 二、使用类问题

**Q：我的项目很小，会不会太重？**
S 级模板的全部要求就是：README + `AGENTS.md` + 验证命令 + 变更记录。`init` 生成的 `.ai/` 里也是最小集合。重流程（宪法、注册表、ADR、契约、性能预算）只在 M 级及以上强制。

**Q：不写摘要行不行？**
行，但代价明确：任务包会把所有文件标成"必须读源码"，你就回到了"每次重读"的老状态。建议只给 `risk: high` 和被依赖最多的文件写，通常 10 个以内就能拿到大部分收益。

**Q：摘要由谁写？AI 写的能信吗？**
摘要必须由**读过源码的一方**写。CLI 的 `index --apply` 会校验 `reviewedHash`：如果文件在写摘要之后又被改过，摘要会被拒绝，避免"凭印象写摘要"污染索引。所以信任来自机制，而不是来自"AI 应该不会错"。

**Q：任务包的 token 估算准吗？**
误差约 ±20%（字符启发式：ASCII ≈ 4 字符/token，CJK ≈ 0.6 token/字符，源码按 9 token/行）。足够做预算决策，不适合计费。

**Q：AI 还是坚持满仓库搜索怎么办？**
三件事按顺序做：① 确认 `AGENTS.md` 的第一条硬约束还在（"先要任务包"）；② 把任务包文件**直接贴给** AI，而不是让它自己去找；③ 在任务包第 3 节明确写"不要读取清单以外的文件"。模板里已经内置了这些指令。

**Q：可以改生成的项目里的框架文件吗？**
可以，`.ai/` 在项目里就是项目资产。`upgrade` 会用三态处理：你改过的文件**不会被覆盖**，只会出现在"需人工合并"清单里。`assets`/`docs/architecture/**` 这类路径默认受保护。

**Q：多个项目能共用一份规范吗？**
能，但要通过"同一版本框架 + 各自 `init`"的方式，而不是 submodule 共享目录。项目的自治能力比规范统一更重要——真实项目总有例外，强绑定会逼大家绕过框架。跨项目一致性靠 `.ai/framework.json` 里的 `frameworkVersion` 对比 + CI 统一检查。

**Q：Windows 支持吗？**
支持。CLI 零依赖、跨平台，只用 `node:path`，不依赖 bash。入口是 `.mjs`。开发与自测都在 Windows 上跑通。

**Q：需要联网/装包吗？**
不需要。零依赖，`init` 会把工具链复制进 `.ai/`，离线可用。

**Q：能配合 Cursor / Copilot / 本地模型吗？**
能。所有知识都是纯文本 + 开放格式。`AGENTS.md` 是跨工具标准；Claude 系工具走 `CLAUDE.md` 转发。没有私有格式或数据库。

**Q：`review --drift` 报了很多 info，要不要都处理？**
不必。优先级：`error`（上下文缺失）→ `warn`（摘要过期，会误导 AI）→ `info`（新增文件、文档断链）。`info` 里的 `digest-missing` 值得处理，因为它直接影响下次任务成本。

**Q：`--strict` 什么时候开？**
建议先跑两周只报告不阻断，观察误报率，再打开。打开后要接 git 钩子或 CI，否则等于没开。

## 三、设计类问题

**Q：为什么索引要提交进 git，而不是本地缓存？**
因为它是**共享资产**：换机器、换人、换 AI 都要用；而且变化可以被 review（"这个文件为什么被标成 high risk"）。只有 `.ai/cache/` 是本地临时目录，被 gitignore。

**Q：为什么 `hash` 用 SHA-256 而不是 mtime？**
mtime 在 git checkout、换机器、复制文件时都会变，会造成大量"假变更"→ 摘要被无意义地重写。内容 hash 只在内容真的变时才变。

**Q：为什么阈值（2k 行、30k 行…）是硬编码的？**
因为规则必须可判定、可自动检查。写成"根据情况判断"的规范等于没有规范。这些数字是**默认值**，项目可以通过 ADR 声明例外（写在宪法的"本项目的例外"一节）。

**Q：为什么 CLI 不改源码、不自动提交？**
不可审计。CLI 只做三件事：生成、检测、报告。所有改动由人或 AI 显式完成，并留下任务包与 ADR 的痕迹。

**Q：为什么用"任务包"而不是让 AI 自己决定读什么？**
因为可复现。同样的任务描述、同样的索引，应该得到同样的读取清单（可以 diff）。模型自由探索的结果无法审计，也无法改进。

**Q：这套东西自己怎么维护？**
和它要求别人做的一样：`AGENTS.md` 是入口、`docs/system/` 是规范正文、影响矩阵在 `docs/system/09-change-protocol.md`、提交前跑 `validate.mjs` + `selftest.mjs`。自测会对**每一个**模板包做完整的端到端验证。

## 四、还没解决的问题（欢迎贡献）

1. **超大仓（> 5 万文件）的单索引粒度**：目前建议用 `--area` 分域，但没有内置的"多域索引"机制。
2. **摘要质量的自动评估**：目前靠人看。可行的方向是"让另一个模型只读摘要回答关于该文件的问题，答不出说明摘要不合格"。
3. **任务包估算与实际 token 消耗的自动对账**：目前只能人工对比（任务包第 8 节）。
4. **非文本资产（美术/音频）的索引规范**：目前只给了"不整读"的规则与字段表，缺少自动提取手段。
5. **S 级项目是否真会遵守轻量流程**：需要真实小项目的观察数据。

发现反例请开 issue，附上项目规模与实测数据——这比"建议增加 XX 功能"有价值得多。
