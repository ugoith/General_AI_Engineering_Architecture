# 写一条 ADR

## 先判断：该不该写

**写**：引入/替换依赖或引擎版本；改变模块边界；改变数据契约（schema/API/存档格式）；改变跨模块调用方式；采用或放弃设计模式；做出约束后续选择的决定；规模等级变化。

**不写**：局部实现细节、命名、格式化、单文件内重构、修 bug（除非修法改变了契约）。

拿不准就写一条 8 行的短 ADR —— 比事后考古便宜得多。

## 流程

```bash
ls .ai/decisions/                    # 找到下一个编号
cp .ai/templates/adr.md .ai/decisions/0007-switch-to-postgres.md
# 填写，然后更新 .ai/decisions/README.md 的索引表
```

## 结构（每条 ADR 只记一个决策）

```markdown
# 0007 会话存储从内存改为 Redis

- Status: Accepted          # Proposed | Accepted | Superseded by NNNN
- Date: 2026-03-04
- Deciders: @team-auth
- 影响范围: src/auth, 部署配置, 本地开发流程

## 背景与约束
多实例部署后会话不共享，用户随机掉线（事故 INC-142）。必须在两周内解决，
且不能引入运维团队不支持的新中间件。

## 决策
会话数据存 Redis，key 前缀 `sess:`，TTL 与 token 有效期一致。

## 后果
- 好：多实例共享会话；掉线问题消除。
- 坏：本地开发必须跑 Redis（用 docker-compose 解决）；Redis 故障会导致全员登出。
- 必须接受：新增一个运行时依赖，需要在宪法"技术栈"一节登记。

## 备选方案
- 粘性会话：被否，负载均衡器更换后失效，且无法灰度。
- 数据库存会话：被否，写放大明显，已有 DB 压力。

## 回退条件
若 Redis 运维成本超过收益（例如引入专职运维或多次故障），改回数据库方案，
迁移路径见本 ADR 的附录。
```

## 硬性要求

| 项 | 要求 |
|---|---|
| 一句话决策 | "决策"一节必须能用一句话说清，用主动语态（"改为…"而不是"考虑…"） |
| 备选方案 | 至少 2 个，且写明**为什么放弃**；只写"选择了 A"的 ADR 没有价值 |
| 坏后果 | 必须写。没有坏后果的决策通常是没想清楚 |
| 回退条件 | **最容易被漏掉但最有价值**：什么情况下应该推翻它 |
| 状态维护 | 决策被推翻时**不要删旧 ADR**，改为 `Superseded by NNNN` 并新建一条 |
| 长度 | 30–80 行。超过 80 行通常说明把多个决策混在了一条里 |

## 反例

- ❌ 写成"设计文档"：把实现细节、代码片段、字段列表全塞进来。ADR 记的是**选择与理由**，不是实现。
- ❌ 事后补写但不注明：补写历史决策时，在 `Date` 后加"（回溯记录）"，说明当时的证据是回忆而非原始记录。
- ❌ 只写选定方案：未来的人无法判断"是否还有更好的选择"。
- ❌ 把 ADR 当成讨论贴：状态停留在 `Proposed` 超过一个迭代且无人推进时，要么定案要么关掉。

## 与其他文档的分工

| 内容 | 去哪 |
|---|---|
| 选了什么、为什么、何时该改 | ADR |
| 系统现在长什么样 | `docs/architecture/overview.md` |
| 具体字段与接口签名 | `.ai/registry.json` + `docs/architecture/interfaces.md` |
| 这次改了什么 | 任务包 `.ai/tasks/*.md` |
| 改了 A 要同步改什么 | `.ai/index/impact-map.json` |
